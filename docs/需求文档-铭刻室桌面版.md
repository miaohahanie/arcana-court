# 需求文档 · 《铭刻室》桌面版（文章管理工具）

> 状态：**v1.0 已确认**（2026-09-04，四项决议见 §8）
> 日期：2026-09-04

## 1. 背景与目标

博客「奥术之庭」已部署于 GitHub Pages，写文章目前依赖：本地跑 serve.py + 浏览器铭刻室 + 手动 git push。
目标是做一个 **Windows 桌面应用（双击即用的 exe）**：

- 双击打开 → 直接进入写作/管理界面，无需先开服务器、无需敲命令行
- 写完点发布 → 自动落盘 + 自动 git commit/push → 约 1 分钟后线上可见
- 同时充当**文章管理中心**：浏览、编辑、下线已有卷轴

## 2. 用户与场景

- 唯一用户：博客主人 miaohahanie（读者不接触此工具）
- 典型场景：打开 exe → 写一篇新文章（或改一篇旧的）→ 点「上传」→ 关掉 → 线上自动更新

## 3. 功能需求

### P0（首版必须有）

| 编号 | 功能 | 说明 |
|---|---|---|
| F1 | 文章列表 | 按日期倒序列出全部卷轴：符印、标题、流派、日期、状态（已发布/草稿）；双击进入编辑 |
| F2 | 新建/编辑 | 与网页版铭刻室同构：标题、分类（可新建）、日期（自动月相）、符印、slug、摘要、正文（Markdown 子集）+ 实时显影预览 + 字数/咒读统计 |
| F3 | 草稿箱 | 未发布的稿子自动保存在本地，重开不丢；一键「继续写作」 |
| F4 | 一键发布 | 落盘 posts.user.json/js → git add/commit/push（复用已配好的 SSH 密钥 arcana-court）→ 显示推送结果与线上链接 |
| F5 | 发布队列与失败重试 | push 失败（断网）时文章标记「待推送」，工具内一键重试全部 |

### P1（首版尽量带上）

| 编号 | 功能 | 说明 |
|---|---|---|
| F6 | 删除/下线 | 下线 = 从线上移除但保留本地存档；通过"下线名单"机制实现，不动手写卷轴原文件 |
| F7 | 图片插图 | 拖拽/粘贴图片 → 自动存入仓库 images/ 目录 → 正文插入引用 → 随发布一起推送，线上直接显示 |
| F8 | 设置页 | 仓库地址、分支、SSH 密钥路径、自动推流开关、博客本地预览端口 |

### P2（未来再说）

- 定时发布（到点自动 push）
- 文章数据统计（字数曲线、发布频率）
- 多博客/多仓库配置

## 4. 技术方案（提议）

- **壳**：Python + pywebview（原生窗口内嵌网页界面，可完整复用博客的紫色魔法视觉与现有编辑器逻辑）
- **打包**：PyInstaller → 单文件 exe（约 30–45MB，双击运行，无需安装 Python）
- **核心动作**：直接读写项目目录里的 `posts.user.json`/`posts.user.js`（不再需要 HTTP 接口），发布时调用本机 `git`（add → commit → push，SSH over 443 通道已验证稳定）
- **依赖的现状**：复用 `~/.ssh/arcana-court` 密钥与 GitHub 仓库 `miaohahanie/arcana-court`；线上部署继续走现有 GitHub Actions 工作流
- **serve.py 退役**：工具上线后，serve.py 的上传职责由 exe 直接接管（serve.py 保留仅作本地预览备选）

## 5. 数据流

```
写作界面 → 保存草稿(本地)
        → 发布:  posts.user.json(+js) 更新
                → git commit "✍️ 文章《标题》"
                → git push (SSH/443)
                → GitHub Actions 自动构建
                → ~1分钟 后 Pages 线上可见
```

## 6. 非目标（本期不做）

- 读者侧任何功能（评论、点赞仍在网页端，已实现）
- 多账号/多博客
- 在线版铭刻室的功能增强

## 7. 验收标准

1. 换一台没有 Python 的 Windows 机器，双击 exe 可正常写作与发布
2. 发布一篇文章后 ≤2 分钟，线上页面出现该文章
3. 断网发布 → 提示待推送 → 恢复网络后一键补推成功
4. 编辑一篇已有文章并发布 → 线上内容同步更新
5. 下线一篇文章 → 线上消失、本地存档仍在

## 8. 已确认决议（2026-09-04）

| 决策点 | 结论 |
|---|---|
| 界面形态 | **魔法风窗口**——优先 pywebview 原生窗口；若运行环境不可用，自动退化为"本地服务 + 默认浏览器打开"（同一套界面），两者皆打包进 exe |
| 推送时机 | **发布即自动推流**，设置里可开关；推流失败自动标记"待推送"，列表页可一键补推 |
| 图片支持 | **本期实现**：拖拽/粘贴/选择图片 → 自动存入仓库 `images/` 目录 → 正文插入引用，随发布推送 |
| 管理范围 | **全部文章可管**：数据主源迁移至 `posts.user.json`（含手写六卷），删除 = 下线墓碑机制（线上移除、本地可恢复），`posts.js` 保留为初始存档 |

## 9. 补充设计（依决议细化）

- **数据主源**：`posts.user.json` 承载全部文章；`posts.user.js` 为站点读取的自动生成镜像；`posts.js` 冻结为创世存档。墓碑条目（`deleted: true`）会让线上合并逻辑跳过该 slug。
- **发布管线**：写 `posts.user.json` + 重生成 `posts.user.js` → `git add -A` → `git commit`（自动补全仓库级作者身份）→ `git push`（SSH over 443，密钥 `~/.ssh/arcana-court`）→ Actions 自动上线。
- **图片管线**：`图片 → images/<slug>-<时间戳>.<ext> → 正文插入 ![图片](images/…) → 随发布推送`；仅收 png/jpg/webp/gif，单张 ≤ 10MB。
- **配置与草稿存放**：`%APPDATA%/ArcanaScribe/`（不入仓库），含 `settings.json` 与 `drafts.json`。
- **本地服务地址**：`http://127.0.0.1:8517`（浏览器模式自动打开；端口被占则自动顺延）。
